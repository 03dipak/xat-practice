## 4. THE FOUR DEFECTS THAT MATTER MOST

All found by RUNNING the thing. None was visible by reading it. Each is now a
test named after what it disproves.

1. **THE COMMIT BARRIER WAS THEATRE.** The first bundle had one loader for both
   the stem and the key, so `answerkey.json` -- every key, every solution, every
   misconception -- was in memory and in the network tab before the learner
   committed a character. Every test on it PASSED, because each checked one
   property and none checked the fetch path. Fixed by splitting `paper.json`
   (loads on load) from `answerkey.json` (fetched inside `check()` only). The
   key field is named `k`, not `key_index`, because a served script that NAMES
   the answer field is one refactor from shipping it. Guard:
   `test_paper_json_alone_cannot_mark_an_answer`.

2. **`G11` DELETED THE HARD RUNG.** It apportions the 20-item PAPER mix; on 4
   items that gave `{1,1,1,0}` and dropped HARD. The product's central claim,
   killed by a paper-level rule. `MIX_ENFORCEMENT_FLOOR = 8`.

3. **DISPLAY STRINGS ARE NOT ARITHMETIC.** All four Lesson 1 keys were REFUSED
   on the first run because `Rs 200` and `2 : 3` do not parse as sympy. Worse,
   `14,400` does not FAIL -- `sympify` returns the TUPLE `(14, 400)`, so a
   thousands separator slips PAST the parse check. Hence `Item.option_values`
   plus `G14_option_value_matches_label`.

4. **THREE CRASHES ON BAD INPUT, all the same family.** `IndexError` in `run`
   (killed a whole paper); `AttributeError` in `_value_visible_in_label`
   (crashed on the exact input `G14` was built to catch); `ValueError` from
   `zip(strict=True)` (killed every LOGIC and JUDGEMENT item).
   **A gate that raises has silently become a gate that is not run.**

Also retired, with reasons in docs/DECISIONS.md section 4: `HOLD` for a
judgement key; `run(..., expected=n)`; the one-comparison `G10`; the flat +0.8
near-miss bonus; `G11`'s defensive `kept.remove`.
